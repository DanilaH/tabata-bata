# Архитектура

`TimerEngine` — чистый Kotlin, источник времени передаётся явно. Deadline текущего этапа сдвигается по расписанию этапов, а не от фактического времени вызова. UI и coroutine лишь запрашивают состояние. Поздний вызов перескакивает через истёкшие этапы без накопленного дрейфа.

`TimerService` владеет engine, sound cues и wake lock. Service стартует пользовательским действием, `START_NOT_STICKY`: нет неожиданного автоматического возобновления. StateFlow передаёт состояние Compose. Уведомление обновляется не чаще раза в секунду и при смене статуса; собственный канал без звука, чтобы не мешать сигналам таймера. Partial wake lock с ограничением длительности отпускается на паузе/завершении/destroy. FGS type `specialUse`, а не `shortService`/`dataSync`: таймер может быть длинным и работать без звуков.

Сессия checkpoint записывается в SharedPreferences раз в секунду и при смене состояния. После нового процесса восстановление только на паузе и вручную. Системные монотонные timestamp не переносятся между перезагрузками.

`Store` — DataStore Preferences для малого структурированного JSON списка и настроек. Room пока не нужен: нет истории, сложных запросов и отношений. Схема обмена v1; импорт проверяет параметры, размер файла до 1 MB, количество до 500, названия до 100 символов. ID импортированных режимов новые, импорт добавляет и не затирает существующее.

`Cues` — SoundPool, заранее загруженные короткие WAV. Новый сигнал отменяет старый; нет TTS/очереди голосовых команд. Ducking опциональный, используется кратковременный audio focus. Автопауза при потере фокуса применима только когда focus запрошен, она не является универсальным детектором звонков. Нельзя обещать распознавание любого звонка без отдельной проверки.

Нельзя считать foreground service абсолютной защитой от OEM ограничения батареи, force stop или системного убийства. WorkManager/AlarmManager не используются как движок двухсекундных интервалов.
