## Подключение SDK

Интеграция в коде: AppMetrica 8.6.0 + Yandex Mobile Ads 8.6.0. По умолчанию API keys/IDs пустые, AppMetrica не активируется, автоматическая инициализация рекламы выключена. SDK входят в APK; фактическое поведение/сбор данных нужно проверить по merged manifest и логам, не обещать «SDK отсутствуют».

Для demo-рекламы:

```sh
./gradlew assembleDebug -PbannerId=demo-banner-yandex -PinterstitialId=demo-interstitial-yandex
```

AppMetrica: `-PappMetricaKey=<test-app-key>`. Использовать отдельное тестовое приложение AppMetrica для debug. В production передать отдельные ID двух форматов. Свободные названия режимов не передаются. Ручного reportAdRevenue нет; фактическую синхронизацию Ads SDK, поступление денежных данных и отсутствие дублей подтвердить в кабинете. Автоматическую работу отдельного Ad Revenue-отчёта без проверки не считать доказанной.

События: `workout_started`, `workout_finished` (completed/stopped, active seconds, pauses/skips), `preset_saved`, `session_recovered`, рекламные request/loaded/impression/closed/error. Impression не равен загрузке. Политика частоты interstitial сохраняется локально, считает успешные завершения, первый пропускает и использует 24-часовой интервал по фактическому onAdShown. Показ только при нажатии «К режимам» после завершения; никогда на «Повторить». Если реклама не готова, пользователь сразу возвращается к режимам, поздний callback её не показывает.

Рекламная интеграция без проверенного показа demo на устройстве и проверки событий в кабинетах не считается валидированной.

## Подпись

Gradle читает `TABATA_KEYSTORE_PATH`, `TABATA_STORE_PASSWORD`, `TABATA_KEY_ALIAS` (по умолчанию `tabata-bata`) и `TABATA_KEY_PASSWORD` из окружения. При наличии этих значений `assembleRelease` создаёт подписанный APK; без них release остаётся unsigned и не подходит для установки/модерации. Production APK перед отправкой должен пройти проверку `apksigner verify`.

Для постоянного ключа создан архив `tabata-bata-signing-backup.zip` с keystore и конфигурацией. Это секретный материал: хранить приватно, не загружать в публичный репозиторий. Debug APK из GitHub Actions использует отдельный тестовый ключ; она не является обновлением подписанной production-ключом версии.

Контакт и ссылка на политику подключаются через `-PsupportEmail=<email>` и `-PprivacyUrl=<https-url>`. При непустых значениях настройки показывают кнопки почты и политики; пустые значения не создают неработающие кнопки. Эти данные требуется заполнить перед публичной сборкой.

## Рекламный проход 0.7.6 — 10 ноября

Источник задачи: экспорт AppMetrica: interstitial 278 request / 264 load error / 10 loaded / 0 impression. Причина SDK-отказов в прежней схеме не записывалась. Баннерный request считал только создание, callback учитывал также refresh: их отношение не является точным fill rate.

- Prefetch только после хотя бы одной завершённой тренировки, на разрешённом экране в foreground и вне дневного лимита. После первой тренировки загружаем заранее для следующей; показ первой по-прежнему запрещён. Тренировка/редактор/настройки/диалоги/фон отменяют запланированные повторы. Уже начатый запрос не дублируется; его поздний успех может заполнить кеш, но не открыть рекламу.
- Не более трёх запросов в серии (паузы 15 и 60 секунд); после третьего отказа нет бесконечного таймера. Через 5 минут новое допустимое действие/возврат может начать следующую серию. Повторы и токены относятся к экземпляру Activity; пересоздание создаёт новый загрузчик/бюджет. Суточный лимит показов сохранён в SharedPreferences.
- Только явное «К режимам» после завершения вызывает show. Stop/Repeat/late load не показывают. Дневной лимит фиксируется на onAdShown; после успешного показа немедленного prefetch нет. Объявление удерживается сильной ссылкой до финального callback. Кеш консервативно устаревает через 45 минут, это наша политика, не заявленный TTL SDK.
- Рекламная поверхность скрыта в фоне и при fullscreen. Стабильный SDK-height и safeDrawing сохраняются. Уничтожение баннера отключает слушатель; callback старого view отбрасывается.
- telemetry schema 2 + app_version: ad_request.attempt (interstitial), ad_error.code (SDK load error), ad_show_attempt/ad_shown/ad_skipped.reason. Banner request.scope=initial_load: SDK refresh не выдаётся за наблюдаемые нами request.
- Demo IDs и production Secrets остаются раздельными. Production-реклама в автоматических тестах не запускается. Реальное наличие инвентаря/статус блока/CPM в РСЯ этим изменением не подтверждаются.

Проверено через GitHub Actions: 28 unit, lint/debug/release, все пять jobs полного CI (Android 8/15/16, совместимость/обновление), независимый аудит, три demo SDK-теста включая actual UI result-to-menu и minified offline smoke — PASS.
