## Подключение SDK

Интеграция в коде: AppMetrica 8.6.0 + Yandex Mobile Ads 8.6.0. По умолчанию API keys/IDs пустые, AppMetrica не активируется, автоматическая инициализация рекламы выключена. SDK входят в APK; фактическое поведение/сбор данных нужно проверить по merged manifest и логам, не обещать «SDK отсутствуют».

Для demo-рекламы:

```sh
./gradlew assembleDebug -PbannerId=demo-banner-yandex -PinterstitialId=demo-interstitial-yandex
```

AppMetrica: `-PappMetricaKey=<test-app-key>`. Использовать отдельное тестовое приложение AppMetrica для debug. В production передать собственные ID. Свободные названия режимов не передаются. Автоматический Ad Revenue SDK остаётся единственным путём сбора выручки, ручного reportAdRevenue нет; корректность и отсутствие дублей подтвердить в кабинете.

События: `workout_started`, `workout_finished` (completed/stopped, active seconds, pauses/skips), `preset_saved`, `session_recovered`, рекламные request/loaded/impression/closed/error. Impression не равен загрузке. Политика частоты interstitial сохраняется локально, считает успешные завершения, первый пропускает и использует 24-часовой интервал по фактическому onAdShown. Показ только при нажатии «К режимам» после завершения; никогда на «Повторить». Если реклама не готова, пользователь сразу возвращается к режимам, поздний callback её не показывает.

Рекламная интеграция без проверенного показа demo на устройстве и проверки событий в кабинетах не считается валидированной.

## Подпись

Gradle читает `TABATA_KEYSTORE_PATH`, `TABATA_STORE_PASSWORD`, `TABATA_KEY_ALIAS` (по умолчанию `tabata-bata`) и `TABATA_KEY_PASSWORD` из окружения. При наличии этих значений `assembleRelease` создаёт подписанный APK; без них release остаётся unsigned и не подходит для установки/модерации. Production APK перед отправкой должен пройти проверку `apksigner verify`.

Для постоянного ключа создан архив `tabata-bata-signing-backup.zip` с keystore и конфигурацией. Это секретный материал: хранить приватно, не загружать в публичный репозиторий. Debug APK из GitHub Actions использует отдельный тестовый ключ; она не является обновлением подписанной production-ключом версии.

Контакт и ссылка на политику подключаются через `-PsupportEmail=<email>` и `-PprivacyUrl=<https-url>`. При непустых значениях настройки показывают кнопки почты и политики; пустые значения не создают неработающие кнопки. Эти данные требуется заполнить перед публичной сборкой.

### Проверки голоса 0.4.0

На физическом телефоне отдельно проверить установленный русский/английский офлайн TTS, отсутствие голоса, музыку с приглушением и без, Bluetooth, выключенный экран, звонок, отключение наушников и окончание занятия. Эмуляторные проверки не подтверждают слышимость. При недоступном TTS приложение использует звуковой сигнал; в настройках показано состояние голоса.

### Проверки сигналов 0.5.0

Новые сигналы 3/2/1, старта и завершения и усиленные виброимпульсы проверить на физическом телефоне, включая выключенный экран. Кнопка проверки вибрации в настройках помогает проверить мотор независимо от громкости. Вибрация и отсчёт включены по умолчанию для новой установки; сохранённые пользовательские выключатели при обновлении не меняются. Системная медиагромкость влияет на звуки. Амплитуда вибрации запрашивается максимальная, но фактическая сила зависит от устройства и системных ограничений.

### Повторные запросы рекламы 0.6.1

При ошибке загрузки interstitial повторяется только предварительная загрузка: через 5, 10, 20, 40, 80, 160 секунд, затем не чаще раза в 5 минут. Одновременно выполняется один запрос; успешная загрузка сбрасывает задержку. Закрытие Ads отменяет ожидание и игнорирует поздние callback. Ошибка показа запускает загрузку следующего объявления, но не повторный показ. Правила частоты и места показа не меняются. Unit-тесты проверяют последовательность ошибок, сброс, отсутствие дублирования и отмену; реальный SDK и события кабинетов всё ещё требуют demo-проверки.
