# Оценки и поддержка — 0.10.0

Дата: 10 ноября 2026. Пакет ru.tabatabata, versionCode 19. Production source: `fe625637f41d16c77d571e180a180db529ffeaeb`; test-only correction: `5d8bab2b6b25616328750dded5409876b913cd58` (прокрутка до кнопки после Activity recreation). Production-код между ними идентичен.

## Поведение

- RuStore Review SDK 10.5.2, официальный Maven. Реальный SDK вызывается только в release и при установленном `ru.vk.store`.
- Предложение возможно только при возврате «К режимам» из успешного завершения: минимум 3 завершённых занятия с выполненными рабочими раундами, 2 разных локальных дня и 10 минут активного времени в сумме. Остановленные, пропущенные целиком и старые записи без достоверной статистики не учитываются. Паузы исключены; фоновое время учитывается по сохранённой статистике движка. Удаление истории не сбрасывает бюджет запросов.
- Максимум 2 автоматические попытки на установку, интервал 30 дней, откат системного времени не даёт повторной попытки. До подготовки SDK бюджет записывается атомарно; ошибка сохранения блокирует SDK. Таймаут подготовки 1500 мс. Меню открывается сразу.
- Навигация, меню карточки, новый таймер, потеря foreground и уничтожение Activity отменяют подготовку; поздний callback не открывает форму. Перед передачей управления ещё раз проверяются экран и lifecycle. После запуска штатной формы её жизненным циклом управляет RuStore.
- Запрос и interstitial используют одну возможность возврата: если выбран запрос оценки, межстраничка в этот момент и после ошибки не показывается. Баннер скрыт до окончания запроса. В течение минуты после отмеченного внешнего действия (почта, ссылка магазина/политики), запроса разрешения или показа interstitial запрос оценки запрещён.
- Нет предварительного вопроса про удовлетворённость, фильтрации по звёздам или вознаграждения. `flow_finished` не означает отправленный отзыв. Известный SDK-ответ «отзыв уже существует» отключает будущие автоматические предложения.
- В настройках отдельная обычная ссылка на карточку RuStore: действие пользователя не зависит от квоты SDK. Аналитика `store_review_open_attempt` учитывает попытку открытия, не факт отзыва.
- «Сообщить о проблеме»: описание до 2000 символов, проверяемые технические сведения (версия приложения/Android/API, производитель/модель, язык), редактируемый почтовый черновик или копирование. Нет автоматической отправки; история, названия режимов, логи и ID устройства не прикладываются. Черновик переживает пересоздание Activity; действия закреплены, тело прокручивается, клавиатура закрывается по Done.
- Приватность обновлена: SDK RuStore содержит техническую аналитику/метрики. Ни оценка, ни текст отзыва не доступны приложению через callback. Новые runtime-разрешения не запрашиваются. Merged permissions сохранены рядом с отчётом.

### Незакрытая рекламная проверка

В demo job 130029190537 баннер загружается (включая SDK refresh) и виден в native скриншоте, но `onImpression` не приходит: два banner-теста FAIL. Actual result → menu → interstitial → close в этой попытке PASS. В свежем повторе 130034333058 та же ошибка баннерного callback; actual UI interstitial показан, но тест не смог закрыть конкретный creative за отведённое время. Minified offline ads smoke после неудачного инструментального шага не запустился. Это не подтверждённая причина на стороне поставщика и не исправляется снятием проверки impression.

Контрольный повтор прежней 0.9.0 без Review SDK, job 130040122537 в [42820631948](https://github.com/DanilaH/tabata-bata/actions/runs/42820631948), PASS: все 3 demo-теста и minified offline smoke. Ads.kt, AdsDemoTest.kt и demo workflow между версиями не менялись. В просмотренных POM RuStore core/analytics/metrics/activitylauncher нет зависимостей Yandex/AppMetrica; SDK Review в debug не вызывается.

Отличие наблюдаемого creative: успешный baseline banner-tree имеет 0 WebView, а баннеры неудачных 0.10.0 имеют 1 WebView (та же рекламная кампания, иное представление). В обеих версиях лог YandexAds сообщает `[Integration] Ad type banner was integrated successfully`; это не заменяет onImpression. Нативный baseline получает callback за ~0.5 секунды после loaded; WebView-вариант не получает его за 90 секунд, включая повторный SDK refresh. Это наблюдение, не доказательство причины на стороне поставщика или безусловной регрессии Review SDK. Повтор текущей 0.10.0 после успешного контроля, job 130046818202, снова FAIL: отсутствует banner impression; actual result → menu → interstitial → close PASS. Этот запуск не подтверждает глобальную недоступность рекламы или однозначную вину нового SDK; корневая причина не установлена. Проверки не ослаблялись, loaded/видимость не подменяют impression, случайные изменения рекламы не вносились.

Рекламная проверка и готовность к публикации остаются открытыми. Следующая диагностика: воспроизвести WebView-creative на реальном устройстве с актуальным WebView; сравнить сетевой/JS-tracker и dependency graph, при необходимости изолированной диагностической сборкой отделить влияние идентичности версии от добавленной SDK-зависимости. Production-настройки рекламы и бюджет показов сохраняются. Подписанная APK предназначена для проверки новых функций, не помечена как готовая к загрузке в магазин.

Предыдущие попытки обнаружили ошибку компиляции callback Activity (исправлена) и неверную UI-проверку без прокрутки после recreation (исправлена). Эти неудачные прогоны не выдаются за успешные. Первый audit job также прервался на соединении с эмулятором до компиляции. Локальный Gradle не смог скачать дистрибутив из-за сетевого ограничения; результаты ниже должны относиться к GitHub Actions.

## Ограничения

Настоящая форма RuStore не проверялась на физическом телефоне с установленным актуальным RuStore, авторизацией пользователя и опубликованным приложением с правильной подписью. Эмуляторные тесты проверяют политику/координатор на поддельном gateway; debug не вызывает реальный запрос. Наличие SDK и успешная сборка не доказывают отображение формы. Квоты и решение магазина могут не дать её показать; приложение продолжит работать.

Проверка почтового intent/копирования не доказывает доставку письма. Публикация в магазине, реальные оценки, изменение удержания, аппаратная слышимость и рекламная выручка этим пакетом не подтверждены. Напоминания, цели недели и достижения в этот пакет не входят.
