# Приёмка 0.9.0: история, недельная сводка и повтор

Дата: 10 ноября 2026. Версия 0.9.0 / versionCode 18 / ru.tabatabata.

## Изменения

История начинается с этой версии: завершённые и остановленные занятия записываются локально. Снимок содержит исходный план, название/оформление, дату окончания, активное время и число уникальных полностью выполненных рабочих раундов. Изменение/удаление сохранённого режима не меняет историю. «Повторить» запускает снимок с новым sessionId, без сохранения режима и ожидания рекламы; «Исходный план» открывает полный preview.

Недельная сводка использует понедельник–воскресенье текущего часового пояса; границы учитывают DST. Дата относится к окончанию занятия, длительность берётся только из монотонного TimerEngine и исключает паузы. SUM/COUNT считает весь диапазон SQLite, независимо от видимых 50 записей. Доступна следующая страница. История без искусственного лимита хранения; очистка всей истории требует подтверждения и не затрагивает режимы/настройки.

Старые checkpoint без статистики помечаются неполными и не добавляют неизвестное время в недельную сумму. Прежние занятия из AppMetrica не импортируются. Отказ от восстановления прерванного занятия не считается обычной остановкой и не создаёт выдуманную запись. Прежний экспорт JSON v1 включает режимы, история в него не входит.

## Надёжность

Service записывает результат, UI его только читает. Один terminal commit в SharedPreferences атомарно заменяет active checkpoint на очередь результата. IO-worker переносит очередь в SQLite; sessionId PRIMARY KEY и INSERT OR IGNORE исключают дубли при повторном переносе. Новый запуск даёт новый ID; восстановление сохраняет ID и метаданные. Тест эмулирует смерть между SQLite commit и подтверждением очереди, повторяя pending запись. Полная очистка сначала удаляет pending записи, затем таблицу, поэтому отложенный worker не возвращает удалённую историю.

Новых SDK, разрешений, сервера или аккаунта нет. Тексты/планы истории не отправляются в аналитику; history_opened/history_repeat передают только факт действия, plan_preview.source расширен фиксированным history. Баннер и interstitial в истории/preview/повторе не показываются; прежняя политика рекламы 0.7.6 сохранена.

## Проверки

Production-код и финальный regression test: 4a9884195afaaa7d7f20b62096c725bf593a8c9d.

- 5 новых unit: границы недели и часовой пояс, DST 167/169 часов, неполная статистика, независимый снимок, остановка с паузой/пропусками.
- 3 repository-теста: атомарная передача/дедупликация, отдельный новый ID, недельная сумма вне видимой страницы, очистка очереди, roundtrip оформления и старые данные. Включены также в совместимость Android 8/15.
- 2 service-теста: фактическое естественное завершение и новый запуск; восстановление checkpoint с прежним ID/именем/цветом и точной статистикой без добавления downtime.
- 3 UI-теста: недельный итог/preview/повтор отсутствующего в saved режима, поворот/recreate, остановка без результата, пустое состояние, подтверждение/отмена очистки, крупный шрифт и длинное имя.

Первый прогон 42817688516: lint обнаружил чтение Configuration через LocalContext; заменено на LocalConfiguration для правильной реакции на смену языка. Из 33 UI-тестов один остановился до прокрутки к лениво создаваемой карточке; исправлен поиск через performScrollToNode. Съёмка ждёт отрисовку native window; дополнительно проверяет доступность заголовка истории. Это исправления кода и проверки, а не основание объявлять первый прогон успешным. Demo 42817688446 и независимый аудит 42817688402 — PASS, первая configured-сборка остановлена lint.

Повторные прогоны выявили гонку в finish: ранний clearResult из инструментального потока обнулял UI Snapshot до сохранения; pending result не создавался, active checkpoint оставался, следующая Activity открывала recovery dialog. Исправлено: finish читает финальный Snapshot из принадлежащего сервису engine. Regression test очищает UI результат сразу после COMPLETED и проверяет сохранение. Запись истории больше не зависит от состояния экрана. Тесты также ждут завершения IO и появления страницы перед прокруткой; обычные скриншоты требуют закрытия диалогов.
